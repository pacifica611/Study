# StudyOS 학습 사이트 기획서 (MVP 중심)

## 1) 제품 정의
- **프로젝트명(가칭)**: StudyOS
- **한 줄 정의**: 시간 관리(캘린더/시간표/타이머/플래너)와 지식 관리(문제 사진/오답/재풀이/복습)를 하나의 학습 루프로 통합한 학습 사이트.
- **핵심 철학**: 기능 나열이 아니라 **매일 학습 루프가 끊기지 않도록 설계**한다.

## 2) 문제 재정의와 핵심 가정
- 사용자는 “기능을 많이 원함” vs 실제로는 루프 단절(계획-실행-복기 불연결)이 문제.
- 서비스는 두 레일로 분리:
  - **Time Rail**: 시간표/캘린더/플래너/타이머
  - **Knowledge Rail**: 문제 사진/오답/재풀이/SRS
- 두 레일은 **PlanBlock(오늘 계획 블록)** 으로 연결.
- 수학 문제 풀이 표기(∞/★//)는 단순 기록이 아니라 **다음 행동 자동 추천 엔진**의 입력으로 사용.

## 3) 타깃 사용자 및 사용 맥락
- **타깃**: 중/고등 학생, 특히 재풀이 루프가 중요한 과목(수학) 사용자.
- **사용 맥락**:
  - PC 웹: 계획/리포트 확인
  - 모바일(PWA): 타이머, 문제 촬영

## 4) 목표 / 비목표
### 목표 (Goals)
1. 오늘 학습 자동 생성(시간표/일정/할 일/복습/재풀이 반영)
2. 타이머 기반 학습 로그 + 과목별 통계
3. 문제 사진 기반 오답 루프(∞/★//) 자동화
4. 미완료 자동 롤오버 + 복습 플랜 자동 생성

### 비목표 (초기 범위 제한)
- 외부 캘린더 완전 연동
- 소셜/스터디 그룹
- AI 자동 해설 생성
- 대형 문제은행 크롤링

## 5) 핵심 도메인 모델
### 5.1 PlanBlock
- 정의: `시간 구간 + 학습 행동` 단위
- 타입: `TASK`, `REVIEW`, `LOOP`, `CLASS`, `EVENT`, `BREAK`
- 상태: `planned`, `done`, `skipped`, `postponed`
- 타이머/결과/미루기 모두 PlanBlock에 연결

### 5.2 ProblemItem (∞/★//)
- `redo_flag` (∞)
- `star_count` (★)
- `wrong_count` (/)
- `next_action`
- 메타데이터: 문제집, 번호, 태그, 사진, 오답 이유, 핵심 포인트

### 5.3 Attempt
- `mode`: `blind` / `with_solution`
- `result`: `correct` / `incorrect` / `unsolved`
- 시도 번호, 소요 시간, 생성 시각

## 6) 사용자 핵심 여정
### 6.1 일일 루프
1. 오늘 화면 진입
2. 자동 생성된 PlanBlock 확인
3. “지금 시작”으로 타이머 시작
4. 완료/부분완료/미룸 + 메모
5. 문제 풀이 시 사진 추가 + 채점(∞/★//)
6. 하루 종료 시 리포트 확인 + 미완료 자동 롤오버

### 6.2 문제 1개 워크플로우
1. 문제 풀이
2. 채점 시 이벤트 기록:
   - 다시 풀 가치: `∞`
   - 못 풂: `★ +1`
   - 틀림: `/ +1`
3. 답지 없이 재풀이(Blind)
4. 필요 시 답/해설 확인 후 재채점
5. 엔진이 NextAction 자동 산출

## 7) 기능 요구사항 (MVP 우선)
### 7.1 오늘 홈
- 오늘 PlanBlock 타임라인
- 시작/완료/미루기
- 미루기 시 다음 가능 슬롯 자동 이동

### 7.2 시간표/캘린더/플래너
- 시간표(주간 반복) 등록
- 단발 일정/시험/마감 등록
- Task(과목/마감/예상시간/우선순위/분할 가능) 등록
- 자동 계획 시 막힌 시간 제외, 마감 가중치 반영

### 7.3 타이머(StudySession)
- PlanBlock 연동 시작/일시정지/종료
- 순공 시간(active time) 기록
- 종료 시 메모 저장

### 7.4 문제 사진 + 오답
- 촬영/업로드
- 문제집/단원/번호/태그 저장
- 오답 템플릿: 원인 + 다음 핵심 포인트 1줄

### 7.5 ∞/★// 엔진 기본 규칙
- ★ 또는 / 발생 시 `RETRY_BLIND` 우선
- ★ 2개 이상: `STUDY_SOLUTION` 우선
- / 2개 이상: `STUDY_SOLUTION` + 오답 포인트 필수
- ∞는 정답이어도 `RETRY_BLIND` 1회 예약

### 7.6 SRS + 자동 복습
- `SrsState(dueAt, interval, ease, reps, lapses)`
- 오늘 due 자동 큐 생성
- 복습 평점(0~3)으로 다음 due 계산
- 단기 재풀이 큐와 장기 SRS 큐 분리

### 7.7 롤오버 정책
- 미완료 TASK/LOOP는 다음 가능 시간으로 이동
- REVIEW는 복습 예산 상한으로 조정
- 미룬 시간/횟수는 통계에서 별도 집계

### 7.8 리포트/통계
- 오늘 순공 시간, 과목별 시간
- 계획 대비 실제
- 완료/미룸 요약
- 재풀이/복습 수행 수

## 8) 자동 계획 생성 로직
### 입력
- 막힌 시간(시간표 + 일정)
- 공부 가능 시간대
- 오늘 SRS due(상한 적용)
- 재풀이 큐(NextAction)
- Task 목록(마감/우선순위/예상시간)

### 출력
- 오늘 PlanBlock 타임라인

### 기본 정책
- 블록 단위 25분
- 복습 예산: 공부 가능 시간의 30% 또는 25분 중 작은 값
- 우선순위:
  1) SRS due
  2) 재풀이 큐(★★ 이상 > // 이상 > ★/ > ∞)
  3) 마감 임박 Task
  4) 일반 Task/신규 풀이

## 9) 정보 구조(IA)
- **오늘**: 타임라인 + 시작/완료/미룸
- **문제**: 문제집/문제 목록, 상태 필터(∞/★//, NextAction)
- **플래너**: Task + 일정/마감
- **리포트**: 시간/성과/품질 지표

## 10) MVP 범위
### 포함
- 오늘 타임라인 + 타이머 + 완료/미루기
- 시간표/일정/Task
- 문제 사진 + ∞/★// + NextAction
- 자동 계획(그리디 배치)
- 데일리 리포트 + 과목별 시간 통계

### 제외
- 외부 캘린더 완전 연동
- AI 기능
- 소셜/공유/랭킹
- 고급 최적화 스케줄러

## 11) 단계별 로드맵
1. **Phase 1**: PlanBlock + StudySession + 시간 통계 + 롤오버
2. **Phase 2**: 문제 사진 + ∞/★// 엔진 + 재풀이 큐
3. **Phase 3**: SRS + 자동 복습 + 품질 지표
4. **Phase 4**: 동기화/백업 고도화 + 외부 연동

## 12) 리스크 및 대응
- 입력 피로: 템플릿 단순화, 버튼 중심 UX
- 복습 과부하: 예산 상한 + 캐치업 모드
- 사진 성능: 자동 압축 + 썸네일
- 웹 제약: PWA 우선

## 13) KPI 제안
- 주 3회 이상 오늘 화면 진입 비율
- PlanBlock 완료율(완료/미룸 비율)
- 재풀이 수행률(∞/★// 항목 중 실제 재시도 비율)
- 블라인드 재풀이 성공률 추이

## 14) 실행 원칙
- “기능 많음”이 아니라 “루프 유지”가 목표
- ∞/★//는 메모가 아니라 **스케줄러 입력 데이터**
- 문제집 status는 “지금 할 일”을 보여주는 집계 UI 중심으로 설계
